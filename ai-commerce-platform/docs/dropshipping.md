# الدروب شيبينج ووكلاء الشراء

المنصة تعمل **بدون مخزون**: لا نشتري الصنف إلا بعد بيعه، ثم نشحنه مباشرة لعنوان
العميل. هذا الملف يشرح كيف تعمل الدورة، والأنماط الثلاثة للوكيل، وقيد الامتثال.

## قيد الامتثال (مهم)

الشراء الآلي المباشر عبر "سكرابنج" لمواقع جوميا/أمازون/نون **يخالف شروط خدمتها**
ويعرّض حساباتك للحظر، وقد يثير مشاكل قانونية ومالية. لذلك:

- **لا** نُنفّذ checkout آلياً على مواقع البيع بالتجزئة.
- الأتمتة الكاملة تتم فقط عبر **APIs رسمية** (حساب أعمال/شريك) — عبر connectors في
  `backend/app/agents/connectors.py`.
- بدون API رسمي، الموردون يعملون بوضع **مساعَد**: الوكيل يجهّز كل شيء والمشغّل ينفّذ الشراء.
- أولكس/دوبيزل إعلانات أفراد بلا API شراء → **يدوي دائماً**.

## دورة الطلب

```
العميل يطلب (COD)
      │
      ▼
وكيل التوريد (sourcing) — تلقائي لحظة الطلب
  • لكل بند: يختار أرخص عرض مورد يحقق هامش ≥ MARGIN_MIN_PERCENT
  • يفتح أمر شراء PO بحالة "بانتظار الموافقة"
  • لا عرض مناسب → "بانتظار التوريد" (تنبيه للمشغّل)
      │
      ▼
المشغّل من لوحة الإدارة (/admin)
  • موافقة → وكيل الشراء يجهّز حزمة الشراء (رابط + كمية + سعر أقصى + عنوان العميل)
  • ينفّذ الشراء لدى المورد، ثم "تسجيل الشراء" (مرجع + تكلفة فعلية)
  • "تسجيل الشحن" (رقم تتبع + شركة شحن)
  • "تأكيد التسليم"
      │
      ▼
حالة الطلب تُحدَّث تلقائياً (جارٍ التجهيز → تم الشحن → تم التسليم)
العميل يتابع كل ذلك من صفحة تتبّع الطلب (بلا رؤية للمورد أو التكلفة)
```

## أنماط الوكيل (`AGENT_MODE` في `.env`)

| النمط | ماذا يفعل عند الموافقة | الاستخدام |
|-------|------------------------|-----------|
| `assisted` (افتراضي) | يجهّز حزمة شراء كاملة وينتظر تنفيذ المشغّل | الإطلاق الآمن بلا API رسمي |
| `simulation` | ينفّذ الشراء آلياً بمرجع وهمي (بلا مال حقيقي) | التجربة والعرض والاختبار |
| `api` | ينفّذ عبر connector المورد الرسمي إن وُجد | عند امتلاك حسابات/APIs رسمية |

`MARGIN_MIN_PERCENT` يضبط أدنى هامش ربح إجمالي يقبله وكيل التوريد (افتراضي 15%).

## دليل المشغّل السريع (النمط المساعَد)

1. سجّل الدخول بحساب إداري ثم افتح `/admin`.
2. تبويب **"بانتظار الموافقة"**: راجع أمر الشراء (المنتج، المورد المختار، التكلفة المتوقعة).
3. اضغط **موافقة** → تظهر **حزمة الشراء**: افتح رابط المورد، اشترِ الكمية بسعر لا يتجاوز
   "السعر الأقصى للوحدة"، واستخدم **عنوان العميل** المعروض كعنوان شحن.
4. ارجع واضغط **تسجيل الشراء** وأدخل مرجع طلب المورد والتكلفة الفعلية.
5. عند شحن المورد: **تسجيل الشحن** (رقم التتبع + شركة الشحن).
6. عند وصول الشحنة للعميل: **تأكيد التسليم** — يصبح الطلب "مكتمل" ويُحصّل الكاش (COD).

للبند "بانتظار التوريد" (هامش غير كافٍ أو بلا عرض): أضف عرض مورد أفضل من قسم الموردين،
أو ارفض البند مع سبب.

## تفعيل connector مورد رسمي لاحقاً

1. احصل على بيانات API الرسمية للمورد (حساب أعمال/شريك).
2. نفّذ `place_order()` في الـ connector المطابق داخل `backend/app/agents/connectors.py`.
3. اضبط المورد على `mode='api'` (من admin API) و`AGENT_MODE=api` في `.env`.

لا حاجة لأي تغيير آخر — وكيل الشراء يوجّه تلقائياً للـ connector.

## تفعيل الأتمتة الرسمية — Amazon Business API (قالب جاهز)

منصتك تتضمّن **قالب connector كامل** لـ Amazon Business في
`backend/app/agents/connectors.py` (الصنف `AmazonBusinessConnector`). الجاهز فعلاً:
تبادل رمز OAuth2 (Login with Amazon) في `_get_access_token()`، وبوابة التحقق من
المفاتيح، وهيكل الطلب. المتبقّي عليك: تعبئة `_submit_order()` بنقطة الشراء الرسمية
حسب نوع تكاملك (API أو Punchout) — لأن أمازون توثّقها لك بعد اعتماد حسابك.

خطوات التفعيل:
1. سجّل **حساب Amazon Business** واطلب وصول API/Punchout.
2. أنشئ ملف أمان **LWA** (Login with Amazon) → client id/secret + refresh token.
3. املأ `AMAZON_BUSINESS_*` في `.env` (انظر `.env.example`).
4. نفّذ `_submit_order()` حسب توثيق أمازون لنوع تكاملك.
5. اضبط مورد أمازون على `mode='api'` (من لوحة الإدارة) و`AGENT_MODE=api` في `.env`.

عندها يوجّه وكيل الشراء طلبات أمازون للتنفيذ الآلي تلقائياً — بلا أي تغيير آخر.

> نون/جوميا لا توفّران API شراء للمستهلك (برامجهما للبائعين فقط)، وأولكس إعلانات
> أفراد بلا API — تبقى كلها في الوضع المساعَد. الأتمتة الكاملة عملياً عبر أمازون
> بيزنس أو مورد دروب شيبينج رسمي يعطيك API شراء.
